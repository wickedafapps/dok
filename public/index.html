Dok Maintenance

          
Maintenance runs in its own privileged container, separate from Dok. Use it to install or reinstall Dok, repair the installation, run updates, manage backups, inspect every container, and run Admin OpenCode. It is started only when you open it here or when Dok needs a host action.

          

            
            
            
          

          
Checking Maintenance status…

          

        

        

          
Installation and core services

          
Dok and its core services are now installed by the Maintenance installer. The Core Services tab only shows services that are already installed, with the same start, stop, restart, domain, and compose controls.

          
Backups, updates, snapshots, repair tools, and the full installation record live beside the checkout in <checkout>-maintenance-data (or MAINTENANCE_DATA_PATH). That folder is separate from the checkout and data/ and is never exported with an app.

        

        

          
Admin OpenCode

          
Admin OpenCode can only run inside the Maintenance container. It has access to the Dok checkout, Docker, and every app so it can troubleshoot and repair the whole installation. Open Maintenance and use its OpenCode panel.
