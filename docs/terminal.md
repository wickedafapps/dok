# Terminal and OC Assist Chat Sessions

Load this file for PTY/WebSocket terminal work, HTTP compatibility transport, session lifecycle, OC Assist chat transport, and OpenCode launch configuration.

## OC Assist chat transport

- OC Assist no longer runs the OpenCode TUI in a PTY. `createAssistChat()` starts one shared on-demand `opencode serve` process on a free `127.0.0.1` port with the User-mode environment, then creates a session through the local OpenCode HTTP API and queues the first prompt with `prompt_async`. Chats live in the in-memory `assistChats` map and are rendered by the native `#assistChatModal`, not xterm.
- `POST /api/assist/start` returns the chat summary after OpenCode accepts the first prompt. Server start, session creation, and prompt failures are returned as `502` with the OpenCode detail, so the UI never opens an empty or dead chat.
- `GET /api/assist/chats/:id` is the chat transport. It reads `/session/:id/message`, `/session/status`, `/question`, and `/permission` from the local server and returns compact messages plus pending questions and permission requests. The UI polls every second while OpenCode is busy or retrying, every 2.5 seconds when idle, and renders streamed text, reasoning, tool calls, changed files, and interactive question/permission cards. Because it is plain HTTP JSON, it keeps working behind proxies that strip WebSocket upgrades.
- Chat actions: `POST /api/assist/chats/:id/prompt` sends a follow-up, `abort` cancels the current run, `stop` aborts and removes the chat, and the `question`, `question/reject`, and `permission` routes answer or skip pending requests.
- Closing the chat modal only stops browser polling. The chat and OpenCode server keep running so the build can finish, and App Creation lists it with an **Open chat** button. **Stop chat** aborts it deliberately and removes it from the list.
- The shared server is capped with the chat map (8 chats). It stops after 30 minutes with no busy or waiting chat and no client polling; `POST /api/core/opencode/stop` stops every chat and the server immediately. If the process exits, the next chat snapshot restarts it and OpenCode restores sessions from the shared data directory. `SIGTERM`/`SIGINT` stop the server with the HTTP server.
- The server and legacy PTY launches use `opencodeConfigForMode()` through `terminalEnv('user', 'opencode', settings)`: `OPENCODE_CONFIG_CONTENT` (the generated mode config, which outranks config files), `OPENCODE_CONFIG`, `OPENCODE_DISABLE_PROJECT_CONFIG=1`, `OPENCODE_DISABLE_AUTOUPDATE=1`, per-mode `HOME`/`XDG_*`, and `OPENCODE_PROVIDER_API_KEY` when a key is configured. Inherited `OPENCODE_*` variables are removed so a host/desktop instance cannot leak its config or session id into a managed session. `PORT`/`HOST` are also removed so an app dev server started by the agent cannot bind Dok's listen port; `WICKEDAFDOK_PORT` carries the real port for `assist-register.mjs`.
- User-mode sessions start in `apps/`, strip Docker/host/credential environment variables, deny `external_directory` except the OC Assist brief/source and registration helper paths, and use explicit bash allows/denies; this is a permission guardrail for the agent, not a separate OS sandbox (the process still runs as the WickedAFDok container user).

## Browser terminal (PTY)

- `createTerminalSession()` spawns `$SHELL -i` (falling back to `bash`, then `sh`) or, for the legacy `app: 'opencode'` API, the resolved OpenCode binary with `node-pty`; sessions are kept in an in-memory `terminalSessions` map and exist only until stopped, exited and reaped, or the server shuts down. The Dashboard terminal is an admin shell; OC Assist does not use this path.
- Limits: 8 concurrent sessions, a 2 MiB rolling replay buffer per session, and a 30-minute idle cleanup for shells after the last client disconnects (legacy OpenCode PTYs use the detached grace below); output is streamed to attached WebSocket clients and the rolling buffer is replayed on connect (the UI resets xterm before applying it). The replay buffer stores `{ seq, data }` chunks so the HTTP transport can resume after a cursor
- A detached shell session is reaped after the 30-minute idle window. A detached legacy OpenCode PTY is kept for one hour (`TERMINAL_OPENCODE_DETACHED_MS`). The session count is capped and exited sessions are reaped, so this stays bounded. HTTP polls update `lastClientAt`, so an attached polling session is not treated as abandoned. The cleanup timer reschedules itself instead of checking once; when the session limit is reached, the oldest clientless session is evicted instead of rejecting the new one
- The WebSocket upgrade at `/api/terminal/ws` validates the `Origin` host against `X-Forwarded-Host`, `X-Original-Host`, and `Host` when an origin is present, so a proxy that rewrites `Host` still works; unknown session IDs get `404`
- If the WebSocket closes before opening (a proxy that strips `Upgrade`, or an origin rejection), the browser switches immediately to `GET /api/terminal/sessions/:id/output` polling plus `POST /api/terminal/sessions/:id/input`, shows a compatibility-mode notice, and keeps the session alive through `lastClientAt`. The HTTP path is intentionally simple: 25 ms input batching, 25 ms polling while draining output, and a 350 ms idle poll
- Server-side protocol pings run every 25 s to keep proxies from dropping an idle socket and to terminate clients that vanished without a close frame. The browser reconnects WebSocket sessions with backoff, rechecks that the session still exists, and does not reset its retry budget until a socket has stayed open for 10 s, so a proxy that accepts and instantly drops upgrades falls back to HTTP instead of looping forever. A socket that opens but never sends the `ready` frame also falls back to HTTP after 8 s. HTTP polling keeps retrying with a capped backoff after repeated failures instead of permanently giving up, and reattaches automatically when the server returns
- `POST /api/terminal/sessions/:id/stop` kills the PTY (with a `SIGKILL` fallback) and closes clients. Closing a shell terminal stops it. Escape closes the terminal modal only when focus is outside the terminal, so a legacy OpenCode TUI can use Escape for its own dialogs without killing the session.
- Closing all WebSocket clients does not immediately kill a session, so a brief reconnect does not lose the shell; it is stopped after the idle timeout
- `SIGTERM`/`SIGINT` stop all live PTY sessions and the shared OpenCode server before the HTTP server closes
